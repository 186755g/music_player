# Frost Player

Frost Player هو مشروع مشغل موسيقى مستقل مصمم ليعمل على Linux Mint باستخدام Electron وTypeScript وVite. يركز هذا المشروع على واجهة داكنة شفافة مستوحاة من Glassmorphism، غلاف ألبوم دائري، مؤثرات صوتية متقدمة، وموازن عشر نطاقات مع كلمات أغاني متزامنة.

## الحالة الحالية

تتضمن هذه المرحلة فقط الهيكل الأساسي الثابت للـ Electron + TypeScript + Vite، مع تقسيم المعمارية إلى طبقات واضحة ومكتوبة نصيًا. لم يتم تنفيذ محرك الصوت، الموازن، أو تكامل MPRIS في هذه المرحلة.

## بنية المشروع

- `src/main` : Electron main process
- `src/preload` : API محمي بين renderer وmain
- `src/renderer` : واجهة المستخدم
- `src/audio` : محرك الصوت المستقبلي
- `src/services/playlist` : مكتبة التشغيل وقوائم التشغيل
- `src/services/lyrics` : خدمة الكلمات
- `src/services/equalizer` : خدمة الموازن
- `src/integrations/linux` : تكامل Linux (مؤجل)
- `src/shared` : الأنواع المشتركة

## متطلبات التشغيل المقترحة

- Linux Mint
- Node.js >= 20
- npm >= 10
- Electron 30.x
- Vite 5.x
- React 18.x

## التشغيل في وضع التطوير

### المتطلبات

- Node.js >= 20
- npm >= 10
- نظام Linux Mint أو أي توزيعة Linux حديثة مع جلسة سطح مكتب قابلة للتشغيل

### تثبيت التبعيات

```bash
npm install
```

### تشغيل التطبيق في وضع التطوير

```bash
npm run dev
```

يُشغّل هذا واجهة Vite فقط، بينما التطبيق الإلكتروني الرئيسي يحتاج إلى ملف Electron منفصل:

```bash
npm run dev:electron
```

### إيقاف التطبيق

- أغلق نافذة التطبيق أو اضغط Ctrl+C في الطرفية التي أطلقت الأمر.

### بناء المشروع

```bash
npm run build
npm run build:electron
```

### بناء حزمة Linux لاحقًا

```bash
npm run package:linux
npm run package:appimage
npm run package:deb
```

### الفرق بين التطوير والحزمة

- `npm run dev` و`npm run dev:electron` مخصصان للتطوير والتصحيح السريع.
- `npm run build` و`npm run build:electron` يقومان بترجمة المشروع لاستخدامه في التطبيق أو الحزمة.
- `npm run package:linux` و`npm run package:appimage` و`npm run package:deb` مخصصة لإعداد الحزمة النهائية لاحقًا، وليس للتشغيل الفوري في هذه المرحلة.

## ملاحظات الأمان

- `contextIsolation` مفعل.
- `nodeIntegration` معطل في renderer.
- API من preload محدود والتحقق من كل مدخل يتم تطبيقه في الطبقة المناسبة.
- لا يفتح المشروع أي ممرات غير آمنة أو أذونات غير ضرورية في هذه المرحلة.
- عمليات اختيار الملفات والمجلدات تمر عبر Electron main/preload API فقط، دون تعريض Renderer للـ Node.js.

## حدود هذا الطور

- لا يوجد محرك صوت فعلي.
- لا يوجد دعم كامل لتنسيقات الصوت.
- لا يوجد تكامل MPRIS أو شريط نظام.
- لا يتم تشغيل build أو التطبيق أو الاختبارات محليًا في هذه المرحلة.

## استيراد الملفات والمكتبة

تمت إضافة طبقة استيراد آمنة تتيح:

- اختيار ملف صوتي واحد أو عدة ملفات.
- اختيار مجلد مكتبة موسيقى إذا كانت آلية الاختيار مدعومة في Electron.
- فحص الامتداد + التوقيع الأولي للملف (بحد أدنى) قبل اعتباره صالحًا.
- التعامل مع إلغاء التحديد كإجراء طبيعي، لا كخطأ.
- إحصاء الملفات المستوردة، غير المدعومة، وغير القابلة للوصول.

### حدود قراءة الملفات

- لا يتم قراءة الملف كاملًا إلى الذاكرة عند استيراده.
- يُقرأ فقط رأس الملف أو يتم التحقق من الخصائص الأساسية مثل الحجم والطبيعة عبر `stat` ونسخة قصيرة من البايتات الأولى.
- لا يتم حذف أو نقل أو تعديل الملف الأصلي.
- إذا اختفى الملف بعد الاختيار أو تعذر الوصول إليه، تُظهر الواجهة حالة غير متاحة مع رسالة واضحة دون كسر واجهة المستخدم.

### تنسيقات الصوت المتوقعة

- `.mp3` و `.wav` و `.flac` و `.ogg` و `.m4a` و `.aac` و `.opus`
- لا يُعتمد الامتداد وحده لتأكيد أن الملف صالح، بل يضاف تحقق من التوقيع المبدئي للملف عند إمكانية ذلك.

## المرحلة الخامسة: مكتبة محلية وقوائم التشغيل

- تم تعريف خدمة مكتبة مستقلة ومفصولة عن محرك التشغيل، داخل [src/renderer/src/library/FrostLibraryService.ts](src/renderer/src/library/FrostLibraryService.ts).
- تدعم الفهرسة، البحث، الفرز، dedupe، قوائم التشغيل، إعادة الترتيب، وعدم حذف الأغاني غير المتاحة.
- تحفظ المراجع إلى الملفات فقط، مع بيانات وصفية قابلة للتطوير، وتبقي المكتبة مستقلة عن تشغيل الصوت.
- تستفيد من واجهة `AudioMetadata` و`LibraryEntry` في [src/shared/types.ts](src/shared/types.ts).

## المرحلة السادسة: Equalizer 10-band

- تم تعريف محرك فاصل ترددات داخل [src/renderer/src/audio/FrostEqualizerEngine.ts](src/renderer/src/audio/FrostEqualizerEngine.ts).
- الترددات: 31Hz، 62Hz، 125Hz، 250Hz، 500Hz، 1kHz، 2kHz، 4kHz، 8kHz، 16kHz.
- كل نطاق يربط بمرشح `BiquadFilterNode` مع `Q` محدد، وقيم رزّ `gainDb` داخل مدي `-12..+12` مع حماية من clipping.
- تشتمل الإعدادات المسبقة على Flat، Bass، Treble، Vocal، Pop، Rock، Jazz، Classic، مع إمكانية حفظ إعداد مخصص.
- لا يتم تشغيل التطبيق أو البناء في هذه المرحلة؛ هذا التوثيق فقط يحدد المسار الصحيح للمعالجة الصوتية في المستقبل.

## المرحلة السابعة: Album Art Rotation و Circular Audio Visualizer

- تم توصيل `AnalyserNode` داخل [src/renderer/src/audio/FrostAudioEngine.ts](src/renderer/src/audio/FrostAudioEngine.ts) إلى المسار الصوتي الفعلي، بحيث يصبح مصدر بيانات المؤثر هو الصوت الحقيقي لا مصدر تجريبي.
- تم إنشاء محرك رسم بصري داخل [src/renderer/src/audio/FrostAlbumArtVisualizer.ts](src/renderer/src/audio/FrostAlbumArtVisualizer.ts)، مع غلاف دائري، حواف متفاعلة، وتدوير ناعم عند التشغيل.
- يركز التصميم على Canvas بدل DOM كثيف، مع إيقاف `requestAnimationFrame` عند إخفاء الواجهة أو عدم الحاجة إلى الرسم، ثم استئنافه عند العودة.
- يراعي الحالة الصامتة، وضع `idle`، و`prefers-reduced-motion`، مع الحفاظ على التدوير مستقرًا عند `Pause` أو عند عدم توفر الإشارة.
- لا يتم تشغيل التطبيق أو البناء في هذه المرحلة؛ هذا هو التوثيق وتنظيم المنطق فقط.

## المرحلة الثامنة: Lyrics Service وعرض الكلمات المتزامنة

- تم إنشاء محلل `.lrc` داخل [src/renderer/src/lyrics/FrostLyricsService.ts](src/renderer/src/lyrics/FrostLyricsService.ts)، مع دعم `title`, `artist`, `album`, و`offset`، وتحليل الطوابع الزمنية مثل `[00:12.50]`.
- يتم فصل parsing عن العرض، مع إخفاء الأسطر غير الصالحة والملفات الفارغة دون انهيار التطبيق.
- يتم حساب السطر النشط بناءً على `currentTime`، مع دعم التمرير التلقائي الناعم ومع إمكانية إيقافه أثناء تصفح المستخدم يدويًا.
- تتوفر رسالة واضحة عند غياب الكلمات، مع تقسيم بيانات التعريف والملفات المحلية والارتباطات دون تعديل الملف الأصلي.
- لا يتم جلب كلمات من الإنترنت أو عرض نصوص تجريبية كحقيقية؛ التوثيق يلتزم بالحدود المطلوبة.

## المرحلة التاسعة: إعدادات Frost Player وحفظ تفضيلات المستخدم محليًا

- تم إنشاء مخزن إعدادات آمن داخل [src/renderer/src/settings/FrostSettingsStore.ts](src/renderer/src/settings/FrostSettingsStore.ts)، مع تخزين محلي موثوق عبر localStorage.
- يحفظ مستوى الصوت، حالة الكتم، الموازن النشط، الإعدادات المخصصة، المظهر، اللغة، الحركة، والسجل الأخير للأغنية وقائمة التشغيل.
- يحافظ على سياسة واضحة: استعادة واجهة فقط، وعدم استعادة ملف موسيقى قديم بطريقة مفاجئة.
- يصف ملف [docs/settings-schema.md](docs/settings-schema.md) مخطط البيانات وسياسة الاستعادة، مع فرق واضح بين Reset Settings وحذف المكتبة.
- لا يتم تخزين الملفات الموسيقية كاملة داخل إعدادات التطبيق، ولا يُسمح لأي مدخل renderer بكتابة مسارات عشوائية.
- لا يتم تشغيل التطبيق أو البناء في هذه المرحلة، والتوثيق يحدد السياسة المنضبطة للتخزين والإعادة.

## المرحلة العاشرة: تكامل Frost Player مع عناصر التحكم بالوسائط في Linux

- تم إنشاء واجهة تصميمية مستقلة داخل [src/renderer/src/integrations/linux/FrostMediaSession.ts](src/renderer/src/integrations/linux/FrostMediaSession.ts).

- توضح [docs/linux-media-integration.md](docs/linux-media-integration.md) ما هو مدعوم فعليًا، ما المؤجل، وكيفية التعامل مع اختصارات لوحة المفاتيح وقيود Media Session.
- لا يتم تطبيق أي أمر shell مركب أو قبول مدخلات من مستخدم غير مصرح به؛ كما لا يُزعم امتلاك جلسة MPRIS لأغاني أو تطبيقات أخرى.
- لا يتم تشغيل التطبيق أو البناء في هذه المرحلة، ويُترك الاختبار الحقيقي إلى الجهاز المستهدف.

## المرحلة الحادية عشرة: تحسين نافذة Frost Player وتوافقها مع بيئات Linux Mint

- تم ضبط BrowserWindow الحالي في [src/main/main.ts](src/main/main.ts) ليبقى آمنًا مع `contextIsolation` و`nodeIntegration: false` و`webSecurity: true`، مع إضافة حسٍّ أخف وزوايا مستديرة وشكل آمن للنافذة.
- توضح [docs/window-shell.md](docs/window-shell.md) سياسة الشفافية واستعادة الخلفية الداكنة البديلة، مع مراعاة كون `backdrop-filter` ليس ضمانًا لطمس سطح المكتب نفسه.
- يتم احترام HiDPI، أحجام النوافذ، وأشرطة العنوان وأزرار التحكم، مع منع انزلاق النافذة خارج الشاشة أو التسبب في مناطق غير قابلة للنقر.
- لا يتم اعتماد Hyprland أو Quickshell أو أي واجهة نظام خاصة، وتُترك القيود المعروفة للشفافية على Linux مختلفة حسب البيئة.
- لا يتم تشغيل التطبيق أو البناء في هذه المرحلة، فقط التوثيق والتعديلات الآمنة للنافذة.

## قرارات التقنية

- تم اعتماد Vite كأداة بناء للـ renderer، مع TypeScript كطبقة ثابتة أساسية.
- تم اعتماد Electron كنقطة دخول سطح المكتب.
- تم اعتماد React لواجهة المستخدم لأنّه مناسب لواجهة Glassmorphism الحديثة ومعالجة UI المركبة.
- تم الفصل بين طبقات main/preload/renderer لتقليل الوصول المباشر إلى النظام.

## ملاحظات Linux Mint

- المشروع مستهدف إلى Mint/Ubuntu/GTK desktop environment.
- التوافق الفعلي مع Wayland/X11 يعتمد على دعم Electron للبيئة الحالية.
- يفضل تنفيذ تكامل المجلدات والملفات عبر مسارات التثبيت الافتراضية وعدم الاعتماد على أدوات Linux غير ثابتة.
